# Tier 1 system

This document explains the Tier 1 workflow used in this repository for validating fit outputs against frozen reference values.

## What Tier 1 is

Tier 1 is a lightweight regression and safety-net system for the fit workflow. It is designed to:

- keep a frozen copy of expected repository state and analysis-reference values,
- verify that the repository still behaves as expected after local or lxplus changes,
- make it easier to compare new fit outputs against known-good reference values.

The system is intentionally simple and focuses on reproducibility rather than full production-scale validation.

---

## Main files

### 1. [python/analysis_reference.py](../python/analysis_reference.py)

Purpose:
- build an analysis-style reference payload from available data,
- prefer real fit outputs when they are present,
- fall back to deterministic placeholder values if no useful outputs exist.

What it does:
- reads the fit log and BH results from the fit output directory,
- extracts fit parameter values such as `nbkg`, `p2`, `p3`, `p4`, `p5`, `p6`, and `p7`,
- reads `BHresults.json` for the bump-hunter probability value,
- writes or reads a JSON payload used by the regression test.

Why it matters:
- this is the core logic that turns fit outputs into structured reference values for testing.

### 2. [tests/test_analysis_reference.py](../tests/test_analysis_reference.py)

Purpose:
- verify that the analysis-reference payload generated by the code matches the frozen reference file.

What it checks:
- the generated payload is serialized correctly,
- the fitted parameter values match the frozen values,
- the bump-hunter probability value matches the expected reference.

Why it matters:
- this is the main regression test for the fit-derived reference workflow.

### 3. [tests/test_repo_utils.py](../tests/test_repo_utils.py)

Purpose:
- verify that the repository snapshot helper produces a deterministic result.

What it checks:
- repository root detection,
- presence of key directories and files,
- stable snapshot contents.

Why it matters:
- this protects the repository layout and ensures the snapshot logic does not silently drift.

### 4. [python/repo_utils.py](../python/repo_utils.py)

Purpose:
- provide repository-level helper functions used by the frozen snapshot test.

What it does:
- finds the repository root,
- builds a deterministic snapshot of important files and directories.

Why it matters:
- the snapshot is used as a second safety net alongside the analysis-reference test.

### 5. [tests/references/analysis_reference.json](../tests/references/analysis_reference.json)

Purpose:
- frozen reference values for the analysis-style payload.

What it contains:
- fit parameter values extracted from the fit run,
- BH probability value,
- empty list for CLs limit points in the current setup.

Why it matters:
- this is the expected-good output used by the regression test.

### 6. [tests/references/repo_snapshot.json](../tests/references/repo_snapshot.json)

Purpose:
- frozen reference for the repository snapshot test.

What it contains:
- a stable description of important top-level files and directories.

Why it matters:
- this ensures the repository structure does not change unexpectedly without a deliberate update.

### 7. [scripts/quality_check.py](../scripts/quality_check.py)

Purpose:
- provide a single entry point for the Tier 1 quality checks.

What it does:
- runs the selected pytest regression tests,
- runs Ruff for linting,
- runs Black for formatting checks on the relevant Python sources.

Why it matters:
- this makes it easy to run the Tier 1 checks in one command.

### 8. [scripts/run_anaFit.sh](../scripts/run_anaFit.sh)

Purpose:
- launch the fit workflow from the repository root.

Why it matters:
- this is the fit entry point used to generate the outputs consumed by the reference logic.

## How the workflow works

The Tier 1 workflow is built around the following flow:

1. Run a fit with the repository’s fit launcher.
2. Gather the relevant output files, especially:
   - `run/fits/run_135_1000_sevenPar/quickFitLog_anaFit_sevenPar_bkgOnly.log`
   - `run/fits/run_135_1000_sevenPar/BHresults.json`
3. Use [python/analysis_reference.py](../python/analysis_reference.py) to build a JSON payload from those outputs.
4. Compare that payload to the frozen reference in [tests/references/analysis_reference.json](../tests/references/analysis_reference.json).
5. Use the snapshot test to ensure the repository structure remains consistent.
6. Run the quality gate through [scripts/quality_check.py](../scripts/quality_check.py).

## Relevant commands

Run the Tier 1 regression tests locally:

```bash
python -m pytest tests/test_analysis_reference.py tests/test_repo_utils.py -q
```

Run the full repository quality gate:

```bash
python scripts/quality_check.py
```

Run the fit:

```bash
./scripts/run_anaFit.sh
```

Run the fit from the repository root on lxplus:

```bash
cd /afs/cern.ch/user/h/hhook/FrequentistFramework
./scripts/run_anaFit.sh
```

Run the regression tests on lxplus:

```bash
cd /afs/cern.ch/user/h/hhook/FrequentistFramework
python3 -m pytest tests/test_analysis_reference.py tests/test_repo_utils.py -q
```

Push local changes:

```bash
git add <files>
git commit -m "Describe your change"
git push origin HEAD
```

Pull the latest changes on lxplus:

```bash
cd /afs/cern.ch/user/h/hhook/FrequentistFramework
git pull origin HEAD
```

Commit and push fit outputs from lxplus:

```bash
cd /afs/cern.ch/user/h/hhook/FrequentistFramework
git add -f run/fits/run_135_1000_sevenPar
git commit -m "Add fit outputs from lxplus run"
git push origin HEAD
```

## Notes for users

- The Tier 1 workflow is meant to be lightweight and repeatable.
- The most important files for day-to-day use are:
  - [python/analysis_reference.py](../python/analysis_reference.py)
  - [tests/test_analysis_reference.py](../tests/test_analysis_reference.py)
  - [tests/references/analysis_reference.json](../tests/references/analysis_reference.json)
  - [scripts/quality_check.py](../scripts/quality_check.py)
- If the fit output format changes, update the parser in [python/analysis_reference.py](../python/analysis_reference.py) and refresh the frozen reference values in [tests/references/analysis_reference.json](../tests/references/analysis_reference.json).
- If the repository structure changes in a meaningful way, update [tests/references/repo_snapshot.json](../tests/references/repo_snapshot.json) accordingly.
- The fit outputs are not automatically tracked by normal `git add`; because the repository ignores generated output, force-adding may be required with `git add -f`.

---

## Recommended workflow

For normal use:

1. make changes locally,
2. run the Tier 1 tests,
3. push the code changes,
4. pull them on lxplus,
5. run the fit,
6. inspect the outputs,
7. commit and push the resulting fit artifacts if needed,
8. pull them back locally for inspection.

This is the workflow that keeps the repository, the regression tests, and the fit outputs in sync.
